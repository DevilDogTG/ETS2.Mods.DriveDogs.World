# ADR-0004: World owns the semaphore timing for flashing green and fixes base-game data that floods game.log

- Status: accepted
- Date: 2026-10-03

## Context

- The DriveDogs Better Flares Traffic Lights add-on (`BetterFlaresAddOns/TrafficLights`) lights the green lens during
  the engine's `green_trans` state. A semaphore model only has that state when its `state_transition[]` gives green a
  transition time. The engine finds a semaphore model by unit id (`tr_sem_mdl.<model>[.<country>]`), so that value can
  only be set in whole copies of `def/world/semaphore_model*.sii`. World already ships those files (Cip's crossing
  sounds), and loads below Better Flares and the add-on, so a copy in the add-on would drop World's crossing sounds.
- DBM Road Signs & Markings 2.1 shipped 4x textures for every sign symbol and frame. Sign atlas
  (`def/sign/atlas/*.sii`) and frame (`def/sign/frame/*.sii`) definitions give texture coordinates in pixels, and 2.1
  shipped none, so since World 1.0.0 every sign drew the top-left quarter of each image. DBM 2.3 adds the definitions.
  `megapack check` cannot see this: every path is valid, only the numbers disagree.
- Base 1.61.1.1 has data bugs that write to game.log on every drive: five signs that are both instanced and LOD'd
  (two Iberian street lamps, three polar-circle signs; 170 warnings per drive through Spain), and the Class 334
  locomotive's glass material still pointing at Class 252's pre-1.61 path (`/vehicle/ai/train/class252/`).
- grass_4.0's grass density (26; base 35) put 77,647 blades of one model on a terrain item, over the engine's
  65,535 per instance cluster, so that item drew no grass.

## Decision

1. **World carries the flashing-green timing** as `base_edits` (`world/traffic_lights.yaml`): `state_transition[]:
   [0, 0, 0, 3.0]` on the 108 standard traffic-light models (base, polar circle, Benelux reskin, Iberia, West
   Balkans). The file is generated by the TrafficLights repo (`tools/generate_traffic_lights.py --world-edits`), which
   owns the flash length and the target list for both halves. Without the add-on those lights go dark for the last
   3 s of green; the description says so in red.
2. **DBM's sign definitions ship with its textures** (source updated to 2.3). A definition follows the texture that
   wins: the 5 gas-station atlases whose texture real-companies wins keep the base game's definitions (excluded in
   `sources.yaml`). `tools/check_sign_defs.py` (read-only, after `megapack lock`) checks every shipped definition's
   pixel coordinates against the winning texture's size.
3. **Base-game data fixes are generated, never hand-copied:** `tools/sign_lods.py` (`world/signs.yaml`) unsets the
   unused LODs of every base sign that is also instanced; `tools/base_material_fixes.py` writes corrected copies of
   listed base materials to `overrides/` (only materials seen in a test log; the base has 153 broken texture
   references, nearly all on unplaced models). Both fail after a game update when the base changes under them.
4. **World's own grass density is 30** (`OURS` in `tools/harvest_graphics.py`, over grass_4.0's 26): about 1.35x the
   base game's grass with headroom under the cluster limit.

## Consequences

- World 1.2.0 needs the TrafficLights add-on for the standard lights to look right; the two release together.
- A DBM update needs `check_sign_defs.py` (it is in the README's build steps and source-update row).
- game.log in a normal drive is free of World's own lines; what remains belongs to other mods (handed over to AI
  Traffic and Trailers & Cargo as their plans `log-errors-161`), the telemetry plugins or base-game data World does
  not own.
- `overrides/automat/` is shared by `rain_reflections.py` and `base_material_fixes.py`; each refuses a path the
  other's manifest lists.
